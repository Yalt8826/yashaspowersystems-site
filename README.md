# personal-site

Static site built with **Astro**, deployed to **Cloudflare Pages** via Git integration.

Two pages for now — a home page and a privacy policy — structured so more can be added
by dropping a file into `src/pages/`.

---

## Quick start

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # outputs to dist/
npm run preview  # serve the built dist/ locally
```

Node version is pinned in `.nvmrc` (22.16.0) to match Cloudflare's build image.

---

## ⚠️ Fill this in before deploying

Everything site-wide comes from **one file**: [`src/site.config.ts`](src/site.config.ts).
Edit it and the header, footer, `<title>`, canonical URLs, sitemap and privacy policy
all follow. The values that must change:

| Field | Currently | Set it to |
| --- | --- | --- |
| `name` | `Your Name` | your name / site name |
| `domain` | `https://example.com` | your real domain, **no trailing slash** |
| `tagline` | placeholder | one line about you |
| `email` | `hello@example.com` | the address shown publicly |
| `legalEntity` | `Your Name` | who is legally responsible for the site |
| `country` | `India` | governing jurisdiction |
| `privacyUpdated` | `2026-09-24` | bump when you edit the policy |

> The privacy policy is a good-faith, factually-accurate template describing what this
> site actually does. **It is not legal advice.** If you later add analytics, cookies,
> embedded third-party content, a contact form or payments, update that page — those
> all change what you must disclose.

## Cloudflare Pages settings

When connecting this repo, use exactly these values:

| Setting | Value |
| --- | --- |
| Framework preset | **Astro** |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory (advanced) | *(leave blank — repo root)* |
| Production branch | `main` |

Cloudflare installs Node 22.16.0 by default in its v3 build image; `.nvmrc` pins it
explicitly so a future image bump can't silently break the build.

**Do not point the output directory at the repo root.** The contents of
`dist/` *are* the website. Building produces the folder; Cloudflare uploads it.

```
├── package.json
├── .nvmrc                   # pins Node for Cloudflare's build
├── public/                  # copied to dist/ verbatim
│   ├── _headers             # HTTP response headers (Cloudflare-specific)
│   ├── robots.txt
│   └── favicon.svg
└── src/
    ├── site.config.ts       # ← SINGLE SOURCE OF TRUTH, edit this
    ├── styles/global.css    # design tokens + base styles
    ├── layouts/Base.astro   # <head>, header nav, footer
    └── pages/
        ├── index.astro      # → /
        ├── privacy.astro    # → /privacy
        └── 404.astro        # → /404.html
```

### Adding a page

Create `src/pages/about.astro` and it becomes `/about` at build time. Then add it to
the `NAV` array in `src/site.config.ts` to put it in the header.

## Cloudflare-specific files

### `public/_headers`

Ships as `dist/_headers` and is consumed by Cloudflare Pages — it is **not** served as a
web page. Applies security headers to everything and long-lived caching to Astro's
content-hashed assets. Limits: 100 rules, 2000 chars per line.

Note: `_headers` does **not** apply to responses generated by Pages Functions (SSR). This
site is fully static, so that doesn't apply — but it would if you switch to SSR.

### `404.html`

`src/pages/404.astro` builds to a top-level `dist/404.html`. **This file is load-bearing:**
without a top-level `404.html`, Cloudflare Pages assumes your site is a Single Page App
and returns the home page with a `200 OK` for every unmatched URL — so typos would
silently render your homepage instead of a 404. Do not delete it.

### Sitemap

`@astrojs/sitemap` generates `sitemap-index.xml` at build time from the `site` value in
`astro.config.ts`. Set a real `domain` in `src/site.config.ts` or the sitemap will point
at `example.com`.

## Deployment note

Pushing to `main` triggers a production build. Pushing any other branch creates a preview
deployment at a unique URL. To skip a deployment for one commit, prefix the message with
`[CI Skip]` or `[CF-Pages-Skip]`.

Adding the custom domain is a **separate step** from deploying — see
`cloudflare-github-hosting-research.md` for the domain attachment, CAA-record and
DNS gotchas.
